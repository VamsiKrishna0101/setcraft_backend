# Optional physique photo review

The current photo review is a visual journal and experimental photo-geometry dashboard, separate from weekly workout planning. Existing saved assessments remain readable; no database migration is needed. Older reports have no numeric geometry and must be explicitly refreshed with retained photos or replaced by a new scan.

## Input and consent

`POST /api/body/reviews` accepts one to four distinct labeled JPEG/PNG photos, including a front view. Back, left and right views are optional. Weight is accepted for older clients but the new mobile flow does not request or send it. `consentToPhotoAnalysis` and consent to AI visual analysis must be explicit. Photo saving is a separate choice, off by default.

The server checks an adult profile. Photos are transmitted to the configured AI provider for analysis. When saving is off, photo bytes are not attached to the assessment; the mobile screen can still display its original in-memory photo for that session. The report itself is saved. This is not a claim about the provider's retention policy.

## Analysis and results

`physique_review.ts` handles new reviews. It bypasses the old four-view circumference engine. The local MediaPipe worker has a separate `visual_geometry` mode: one front photo, no height input, no circumference inference. The v1 index compares paired limb contour widths using `100 * min(left,right) / max(left,right)` and averages at least two supported regions equally. Tilt, lean, visibility, yaw, blur and contour-connectivity checks can suppress values. This is an **experimental unvalidated photo index**, not a percentile, health grade, muscle-size measurement, or evidence of muscle growth. The mobile card labels it experimental and stores the geometry version, components and quality notes.

V-taper is detected shoulder joint span / visible waist width. Shoulder balance describes shoulder level; chest balance describes upper-torso contour similarity. Neither measures muscle development. Definition is a separate, explicitly subjective AI rating using a fixed five-band visible-definition rubric; clothing, posing or lighting uncertainty must yield null. OpenAI cannot generate symmetry, body-fat or muscle-mass values.

Optional `compositionReadings` accepts a dated, member-entered smart-scale/DEXA reading (body-fat percent and/or skeletal muscle kg). Source and date are visible in details. Lean/fat-free/appendicular lean mass must not be relabelled muscle mass. Future dates and muscle mass >= profile weight are rejected. `PATCH /api/body/entries/:id/readings` requires authenticated ownership, a saved photo report, premium access and an optimistic timestamp. It changes the report only, not plan inputs. No body-composition provider is configured or claimed validated. Absent readings remain unavailable; no fallback invents numbers.

AI descriptions and local geometry run concurrently. Failure of either source does not manufacture its results; independent available results and member readings can still be saved. Highlight evidence refers only to supplied views. No workout recommendations are generated by photo review.

The same neutral instructions and clothing standards apply to all users. `OPENAI_PHYSIQUE_MODEL` selects the existing configured model. Provider failure saves no invented observations; a clear unavailable state is returned. A saved-photo review can be explicitly refreshed later. A failed refresh keeps the existing report. An unusable photo returns a retake error.

## Comparison

Photo comparison is shown only when two distinct saved, non-synthetic scans have retained photos of the same view, ordered by recorded date and creation time. A single scan, report-only scans and unmatched views do not expose photo comparison. The server also rejects photo-review comparisons without a retained matching view. Measurement comparisons remain available separately.

The mobile studio supports a draggable before/after divider, a regular accessible slider, side-by-side viewing, shared pinch zoom and manual position/scale adjustment of the earlier photo. Alignment changes display transforms only; original photos are unchanged. Photos alone do not establish quantified muscle gain or fat loss.

## Scan reliability and weekly selection

The v2 geometry engine accepts both H×W and H×W×1 MediaPipe masks. A singleton channel is removed before contour sampling; the old shape mismatch caused an internal error on real captures. Metrics are assessed independently: a covered hip or an uncertain outline does not discard a supported shoulder-level result. Fixed upper-torso rows are checked for arm contamination before a chest-contour value is returned. Symmetry still requires two supported paired limb regions, and unsupported values are never filled by an AI guess. Existing v1 results remain readable; v2 records retain their method version and per-metric retry guidance.

The slow top-to-bottom scan sweep is a functional progress indicator and remains active when Android's system animation scale is zero. It stops on completion, failure, cancellation, or a hidden route. Decorative page motion continues to honor reduced-motion settings.

A report-only scan keeps a neutral illustrated background and the complete metrics layout. A member can optionally choose a display-only background photo; it is neither uploaded nor attached to the saved scan. The picker may use temporary local files, while the display selection is scoped to that screen. It cannot alter the saved scores. Missing composition values link to entered readings; incomplete photo metrics show capture/retry guidance.

Physique uses This week, Last week, and a custom whole-week list. Every selection is a local-calendar Monday–Sunday range, including across DST, month and year boundaries. The backend resolves only real active/archived plan days inside that range, choosing the newest saved recommendation per day and using actual scheduled exercise doses. An empty historical week never falls back to the current or next plan. The generation card is shown for the current week only.

## Validation

- `npm run build`
- `npm run test:body:physique` (synthetic input; no provider or database writes)
- Existing `test:body` and `test:body:flow`
- `.body-venv/Scripts/python.exe body_measurement/test_visual_geometry.py` (synthetic contours only)
- Flutter `physique_photo_review_test.dart`, `body_physique_test.dart` and `body_training_refresh_test.dart`

The new app and backend must be released together. Rendered UI tests use an illustration, not member photos. Synthetic arithmetic and contour checks do not establish real-world accuracy or test-retest reliability. Before making progress/accuracy claims, evaluate repeated standardized captures against expert contours across phones, body types, clothing and lighting; calibrate thresholds and quantify measurement error. No such clinical or population validation is claimed here.

## Physique home

The Physique tab always shows its anatomical workout map. `/api/heatmap/plan` maps primary and supporting muscles from the active, non-synthetic personal plan and its actual dated workout items. Rest days, skipped exercises, user edits, completed sessions and archived/expired plans are handled explicitly. The endpoint does not read photo reports. The client refreshes this map directly when returning from workout edits. Photo review and scan history are compact entry rows opening separate screens.
