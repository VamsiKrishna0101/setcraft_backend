# Original 181-food library

The active shared library now contains [300 generic foods](generic-food-catalog.md)
with reviewed images in Cloudflare R2. This document records the original
181-food selection and its history; those identities and nutrient values remain
part of the current catalogue.

The original selection contains 181 foods: eggs, milk, yogurt, oats, breads,
rice, pasta, potatoes, meat, fish, beans, fruit, vegetables, nuts and basic extras.
Names are short; preparation, fat percentages and other important distinctions
remain explicit. Nutrition values are reference compositions, not package labels.

`data/everyday_foods.json` contains the selected source records, exact nutrition
values and provenance. Sources are USDA FoodData Central SR Legacy, the April
2026 Foundation Foods download, and Anses Ciqual 2025. Download checksums and
attribution are included. USDA data are public domain; Ciqual uses the Open Licence.
The Foundation download date does not mean every underlying food was measured in 2026. Food-name translations were generated and should be reviewed before release.
Nutrition values were never generated by AI. Image sources for the current
catalogue, including representative generated illustrations, are documented in
[generic-food-catalog.md](generic-food-catalog.md).

## Quantities

Nutrition is stored per 100 g edible portion. Sourced portions enable large eggs,
peeled bananas and milk volumes. For example, a large boiled egg is 50 g, so two
eggs consume one 100 g nutrition serving. Milk volume uses that record's USDA fluid
ounce weight and the U.S. fluid-ounce conversion, not an assumption that 1 ml = 1 g.
Foods without a supported conversion remain in grams. Package/recipe values can
be entered as custom foods with their own g, ml or portion basis.

USDA carbohydrate-by-difference includes dietary fibre; Ciqual uses its own
published carbohydrate definition. Original values and methods are retained in
source metadata. These averages must not be advertised as exact measurements of
a user's meal or a specific European branded product.

## Replacement and history

Run `node --use-system-ca --import tsx scripts/rebuild_food_catalog.ts` for counts,
then add `--apply` to perform the replacement. The script first writes a backup
under the ignored `build/food-catalog/` folder. A transaction removes unused shared
foods, archives older foods referenced by logs/plans, and installs the selected
catalogue. Existing Ciqual identities retain their exact nutrients and quantities.
Custom foods, meal logs and meal-plan items are compared before commit.

Archival hides a food from browsing and new logging while retaining its history.
Future planner inputs and activation checks require active foods. Existing linked
meal-plan items can still use their original values. New named-plan placeholders
are archived from creation so zero-valued placeholders do not enter food search.

On the initial replacement, 2,217 unused foods were deleted and 181 foods became
the active library. There were no existing custom foods, meal logs or meal-plan
items in that database. The backup retains the original 2,239 shared records.

## Browsing and custom entries

The paginated catalogue supports `LIBRARY`, `RECENT`, `MY_FOODS` and `MY_MEALS`.
Recent contains distinct foods actually logged by the authenticated owner, ordered
by last use. Private entries with category `MEAL` appear under My meals; other
private entries appear under My foods. Search, category, nutrient filters and
sorting work within the chosen section. Advanced filters live in a bottom sheet.

Creating a custom food saves its entered nutrition and logs the selected quantity
when the user taps Log meal. Save as a meal makes it reusable under My meals.
Reusing a meal never logs it automatically on another day.

Optional custom-food photos are small private thumbnails, at most 180 KB. The
picker resizes them before upload. They are stored in PostgreSQL, fetched through
an authenticated owner-only endpoint, excluded from catalogue JSON, and removed
when the custom entry is deleted. The food itself is archived if needed for old
logs. Original full-size photos are not uploaded; there is no meal-photo nutrition
analysis in this flow. Foods without images use category icons.

The client uses a new catalogue cache namespace so the old imported names cannot
reappear from local cached pages. Personal pages are invalidated after meal saves.

## Checks

- `npm run build`
- `node --use-system-ca --import tsx scripts/test_food_catalog.ts`
- `flutter test test/everyday_foods_test.dart test/food_library_view_test.dart test/nutrition_view_test.dart test/nutrition_progress_test.dart`

The API test uses temporary accounts and deletes only its own records afterward.
It covers pagination, localized search, nutrition filters, recent/private scopes,
photo ownership, thumbnail delivery and preserving logs when a custom meal is
removed. Flutter tests cover quantity conversions, cached portion metadata,
section switching, reusable meals, filtering, keyboard layout and form state.
